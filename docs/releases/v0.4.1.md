# nSkinzCS2 v0.4.1 — Input crash fix / 输入闪退修复

Released: 2026-08-30 · Windows x64 · English / 简体中文

## 简体中文

### 主要修复

- **修复使用输入法、在皮肤搜索栏输入文字导致 CS2 闪退的 bug**，包括英文输入也可能触发的崩溃。完整控制面板通过系统自带的 `rundll32.exe` 独立运行，不再在 `cs2.exe` 内创建面板的 D3D11 设备和文字服务窗口。
- 保留中文输入和完整的本机游戏皮肤目录。独立面板读取运行时导出的目录，不以禁用中文或减少涂装选项规避崩溃。
- 修复枪械动态涂装属性与备用字段不同步、造成目标涂装不生效的问题；校验已有属性槽，不替换或扩容游戏属性向量。
- 修复刀材质完成刷新后，因 Demo 回写普通数值而重复生成材质的问题。更换涂装、种子或重建实体仍会正常刷新。
- 修正刀模式：“仅饰面”不显示模型选项，也忽略旧配置残留的刀模选择；“饰面＋模型”才允许选择模型。
- 移除网格更新的 700 次重复写入和阻塞等待/重试循环；改为按需写入、立即校验。运行时使用共享只读目录，帧回调日志由后台批量落盘。

### 下载与加载

- `nSkinzCS2.dll`：英文界面、英文皮肤名。
- `nSkinzCS2.zh-CN.dll`：简体中文界面、中文皮肤名。
- `nSkinzCS2-v0.4.1-windows-x64.zip`：两份 DLL 和中英加载说明。
- `nSkinzCS2-v0.4.1-source.zip`：与本次发布提交对应的源码，不含私人配置、日志、Demo 或游戏截图。
- `SHA256SUMS.txt`：下载文件校验值。

发布 DLL 使用静态 MSVC 运行库，无需另装 Visual C++ 运行库、Python、SDK 或编译器；仍需 Windows x64、CS2 和 HLAE。把 DLL 放入可写文件夹。升级时先备份配置并重启 HLAE/CS2，只加载一个语言版本，不要叠加注入旧版与新版。

仅用于 HLAE `-insecure` 启动的离线 Demo，不用于 VAC 保护服务器或联机服务器。

```text
mirv_loadlibrary "C:/nSkinzCS2/nSkinzCS2.zh-CN.dll"
```

按 `Insert` 打开完整面板，选择玩家和外观配置，再点击“更新”。英文版将路径中的文件名改为 `nSkinzCS2.dll`。DLL 同目录会生成配置、目录快照和日志；面板日志为 `nSkinzCS2.ui.log`，运行日志为 `nSkinzCS2.log`。

### 验证与限制

- 当前源码通过 42 项原生回归测试；两份 DLL 的语言资源、UTF-8 文本及依赖检查通过。
- 同一网格函数 240 次更新：旧实现 3714.43 ms，新实现约 0.1 ms。该数值是独立测试进程中的函数基准，**不是游戏 FPS 实测**。
- 新版非阻塞更新尚未完成整段 Demo 帧率复测，不能宣称所有间歇卡顿均已消失。新增 `Runtime performance` 日志用于定位剩余慢点。
- 部分刀的“原皮（无涂装）”仍可能残留 Demo 中已有的第一人称材质；刀模/动画覆盖与空挂件模块创建仍属实验性功能。
- 输入闪退修复不代表兼容所有输入法、覆盖层或未来 CS2 更新；遇到问题请提供版本、输入法、复现步骤和脱敏日志。

## English

### Fixes

- **Fixed the CS2 crash triggered by IME input and typing in skin-search fields**, including cases triggered by English input. The complete control panel now runs through the system's `rundll32.exe`, outside `cs2.exe`; its D3D11 device and text-service window are no longer created in the game process.
- Preserved Chinese input and the complete installed-game cosmetic catalog via the exported catalog snapshot, without disabling languages or reducing paint-kit choices.
- Fixed dynamic weapon attributes not matching the requested finish. Existing attribute slots are synchronized and verified without replacing or growing game-owned attribute vectors.
- Reused completed knife material refreshes after ordinary demo field rewrites. Actual paint/seed changes and entity rebuilds still request refreshes.
- Hid and ignored model selection in **Finish only** mode; the model selector is available only in **Finish + model**.
- Replaced the mesh updater's 700 repeated writes and blocking sleep/retry loop with changed-field writes and immediate verification. Runtime catalog reads share immutable snapshots, and frame-callback logs are flushed by the background worker.

### Installation

Choose `nSkinzCS2.dll` for English or `nSkinzCS2.zh-CN.dll` for Simplified Chinese. The Windows x64 ZIP includes both DLLs and loading instructions. The source ZIP matches the release commit and excludes private configs, logs, demos and gameplay screenshots. Verify downloads with `SHA256SUMS.txt`.

The DLLs statically link the MSVC runtime: no separate Visual C++ Redistributable, Python, SDK or compiler is required. Windows x64, CS2 and HLAE remain required. Use a writable folder, back up your config, restart HLAE/CS2 when upgrading, and load only one language DLL.

For HLAE `-insecure` **offline demo playback only**; never use on VAC-protected or online servers.

```text
mirv_loadlibrary "C:/nSkinzCS2/nSkinzCS2.dll"
```

Press `Insert`, select the player/profile, then click `Update`. Config, catalog snapshot and logs are generated beside the DLL. Panel diagnostics use `nSkinzCS2.ui.log`; runtime diagnostics use `nSkinzCS2.log`.

### Verification and limitations

- 42 native regression tests pass; both DLLs pass language-resource, UTF-8 and dependency checks.
- The same 240 mesh-function updates took 3714.43 ms before the fix and approximately 0.1 ms afterwards. This isolated-process benchmark is **not an in-game FPS measurement**.
- Full-demo frame-rate verification of the new nonblocking path remains pending. Not every intermittent stall is claimed fixed; new `Runtime performance` records help identify remaining costs.
- Some knife vanilla requests may retain recorded first-person materials. Broader knife model/animation coverage and creating missing keychain modules remain experimental.
- The input fix is not a guarantee for every IME, overlay or future game build. Include versions, input method, reproduction steps and redacted logs when reporting issues.
