# nSkinzCS2 v0.4.2 — 单 DLL 加载完善 / Single-DLL loading

Released: 2026-08-30 · Windows x64 · English / 简体中文

## 简体中文

### 本次更新

- 面板着色器改为预编译后嵌入 DLL，彻底移除 `D3DCOMPILER_47.dll` 的运行时依赖，不需要另行安装或下载着色器编译器。
- 中英文发布版继续使用静态 MSVC 运行库（`/MT`）。除 Windows 10/11 x64、CS2 和 HLAE 外，不需要另装 VC++ Redistributable、DirectX SDK / June 2010 运行库、.NET、Python 或 Visual Studio。
- 修正静态 CRT 的线程通知处理；增加发布 DLL 导入审计和独立加载/渲染回归工具。
- 完善加载说明：使用真实完整路径，避免重复双引号和中文弯引号。用户报告的新 DLL 加载失败在修正路径/引号后确认成功；**不能据此把原始问题归因为缺少 VC++ 运行库**。
- 沿用 v0.4.1 的输入法/搜索闪退修复及换肤逻辑。刀模型开发独立保存，本版本没有引入新刀模、动作或穿模处理。

### 下载与加载

- `nSkinzCS2.dll`：英文版。
- `nSkinzCS2.zh-CN.dll`：简体中文版。
- `nSkinzCS2-v0.4.2-windows-x64.zip`：中英文 DLL、加载说明和发布说明。
- `nSkinzCS2-v0.4.2-source.zip`：对应发布提交的源码，不包含私人配置、日志、Demo 或游戏实测截图。
- `SHA256SUMS.txt`：各下载文件的 SHA-256 校验值。

只需选择一个 DLL。先退出旧的 HLAE/CS2，再通过 HLAE 带 `-insecure` 启动 CS2，打开离线 Demo；不要在同一进程内叠加新旧版或两个语言版本。把 DLL 解压到可写文件夹，目录、配置和日志会自动生成。

例如，中文版实际放在 `D:\nSkinzCS2.zh-CN.dll`，可直接使用下面**不带引号**的完整路径指令：

```text
mirv_loadlibrary D:\nSkinzCS2.zh-CN.dll
```

路径有空格时，只使用一对英文半角双引号：

```text
mirv_loadlibrary "D:\My Tools\nSkinzCS2.zh-CN.dll"
```

请按真实文件位置修改路径；不要写成 `""D:\nSkinzCS2.zh-CN.dll""`，也不要使用 `“…”`。英文版将文件名改为 `nSkinzCS2.dll`。按 `Insert` 打开面板，配置后点击“更新”。

**仅用于 HLAE `-insecure` 离线 Demo。禁止用于 VAC 保护或联机服务器。**

### 验证与限制

- 发布的是已确认加载成功的原始 DLL 字节，不是重新编译后未经确认的另一份产物。
- 本机 9 个加载/离屏渲染对照用例符合预期，覆盖中英 DLL、中文/空格路径、System32-only 依赖搜索和不兼容编译器；实际 ImGui DX11 后端通过 WARP 10.0 像素读回及三次资源重建。
- 现有 42 项原生回归复跑通过；语言资源、中文目录、UTF-8、直接导入及着色器重现检查通过。
- 用户确认朋友的加载问题解决；**这不等于所有纯净系统、覆盖层或所有换肤功能都完成了测试**。本次没有重新进行整段 Demo 帧率/换肤实测。
- 刀原皮第一人称旧材质残留、刀模/动画覆盖、无挂件模块物品的模块创建仍有既有实验性限制。未声称解决所有卡顿。

更多排查见 [单 DLL 加载说明](https://github.com/Lyan-edit/CS2-nskinz/blob/v0.4.2/docs/portable-loading.md)。`LoadLibraryA failed` 是 HLAE 的通用提示，不提供 Windows 错误码，也不一定产生 nSkinz 日志。

## English

### Changes

- Embedded precompiled UI shaders and removed the runtime `D3DCOMPILER_47.dll` dependency. No compiler DLL download or installation is needed.
- Both languages retain the static MSVC runtime (`/MT`). Beyond Windows 10/11 x64, CS2 and HLAE, no separate VC++ redistributable, legacy DirectX runtime/SDK, .NET, Python or compiler installation is required.
- Preserved thread notifications required by the static CRT and added release import auditing plus standalone loader/renderer regression tools.
- Clarified full-path loading and correct quoting. The reported failure with the new DLL was confirmed resolved after correcting the path/quotes; **it was not established to be a missing VC++ runtime problem**.
- Retained v0.4.1's IME/search crash fixes and cosmetic runtime logic. Independent knife-model development remains saved and separate; no new model/animation/clipping changes are included.

### Installation

Download either language DLL or the Windows x64 ZIP. The source ZIP matches the release commit; it excludes private configs, logs, demos and gameplay screenshots. Use `SHA256SUMS.txt` to verify files.

Restart HLAE/CS2, use HLAE `-insecure` offline demos only, and load one DLL from an extracted writable folder. Config/catalog/log sidecars are generated automatically. Do not stack versions or language DLLs. For a file actually located at the following path:

```text
mirv_loadlibrary D:\nSkinzCS2.dll
```

If the path contains spaces, use exactly one pair of ASCII double quotes:

```text
mirv_loadlibrary "D:\My Tools\nSkinzCS2.dll"
```

Never double-wrap quotes or use typographic quotes. Replace the path with your real location; use `nSkinzCS2.zh-CN.dll` for Chinese. Press `Insert` and then `Update` after configuring the panel. Never use on VAC-protected or online servers.

### Validation and limitations

This release preserves the exact DLL bytes from the confirmed successful build. Nine local loader/offscreen-renderer control cases met expectations, including both languages, Unicode/spaced paths, System32-only search and an incompatible-compiler fixture. The actual ImGui backend passed WARP feature-level 10.0 pixel readback and three device-resource recreations. The existing 42 native regressions, localized catalog/text checks, import audit and shader reproducibility checks passed.

The user confirmed their friend's loading issue was resolved. This is not exhaustive clean-OS, overlay or in-game cosmetic coverage. No new full-demo FPS/cosmetic retest was performed. Existing vanilla-knife material, experimental knife model/animation and missing-keychain-module limitations remain; not every stutter is claimed fixed.
