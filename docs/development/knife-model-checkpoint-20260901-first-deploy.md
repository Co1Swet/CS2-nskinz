# 刀模首段出鞘与 HUD 预绑定检查点（2026-09-01）

## 问题证据

当前日志显示，源 CT/T 默认匕首的 deploy 已开始后，独立刀模事务才发现活动刀并执行 world/HUD 重建。因此第一次切刀会出现源刀动作开头、目标刀突然出现或缺少数帧；物品定义也在 HUD 创建后才修改，右侧武器栏仍可能显示源刀。

## 当前实现

- `ModelAndFinish` 模式在目标刀处于收起状态时建立单一预绑定租约。
- 预绑定严格校验 XUID、pawn/world 完整句柄、实体创建代次、所有权、实际活动武器、HLAE、`-insecure`、游戏线程、`FRAME_RENDER_PASS` 和当前 `client.dll` 指令窗。
- 在原生装备流程之前同步目标物品定义、刀饰面属性和目标 world 模型；不写 sequence，不猜固定动画，不修改枪、手套或 arms 模型。
- 若旧 `C_CS2HudModelWeapon` 仍挂在该刀下，等待其删除后再预绑定，避免再次发生活动 HUD 的中途销毁。
- 预绑定成功后的 75 ms 维护路径只读校验物品定义、模型和饰面属性，不重复扫描 HUD、调用 `SetModel`、重建材质或扩展属性向量。
- 配置禁用/换目标、观看玩家改变、拾取换主和 Demo seek 使用原始外观快照与实体代次处理；活动刀的恢复延迟到收刀，避免在目标动画图运行中写回源定义。
- `.drop` 导致句柄、所有者或创建代次变化时，旧租约直接放弃，绝不把旧玩家快照写入新玩家实体。

## 离线 Demo 画面验收

必须完整退出已加载旧 DLL 的 HLAE/CS2，再以 `-insecure` 离线 Demo 新进程只加载一个语言版本。让目标玩家先持枪，等待日志出现 `Holstered knife pre-armed before native equip` 且 `world_model_prearmed=1`，然后第一次切刀。通过标准为：第一帧起即使用目标刀型的原生出鞘动作，目标模型不再中途突然出现，所选涂装与模型同步出现，右侧 HUD 刀图标使用目标刀型；之后切枪再切刀、检视以及 `.drop` 拾取后仍保持一致。
