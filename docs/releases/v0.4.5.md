# v0.4.5 — 枪械应用与轮询卡顿修复 / Firearm apply and polling-stutter fix

Release date / 发布日期：2026-09-02

## 简体中文

### 本次修复

- 修复朋友机器上点击“更新”后枪械换肤不生效的问题。日志中的请求已经到达运行时，但原皮枪械没有涂装、种子和磨损属性，Schema 也没有提供可用的属性向量追加操作，因此旧流程最终为 `changed_slots=0, verified=0`。
- 在当前客户端中解析并逐字节验证原生 `CUtlVector<CEconItemAttribute>::AddToTail` 入口；仅当反射偏移、元素大小和机器码都符合已验证基线时，创建缺失的 paint kit（`6`）、seed（`7`）和 wear（`8`）节点。未知版本或布局会拒绝写入。
- 撤销时不在缺少 erase 回调的情况下破坏或缩短引擎向量；由本工具创建的尾部节点会被中和，后续再次“更新”复用同一节点，避免属性持续增长。
- 修复日志中外观轮询平均约 31 ms 的重复扫描原因。经过验证的实体上限探测现在同时填充缓存，不再在同一轮询中第二次遍历完整实体系统。
- 保留 v0.4.4 的枪型/涂装兼容校验、原皮枪械首次材质生成、新旧网格选择、独立输入面板和单 DLL 便携加载方案。

### 刀模开发状态

当前独立刀模链随 v0.4.5 源码和 DLL 收录，刀模与刀涂装事务、模型资源、动画图、生命周期和 HUD 交接相关代码均与枪械、手套及仅换刀皮肤的链路分离。它仍为**实验功能**：首次实体重建时的出刀连续性、队友发出或 `.drop` 后的刀归属交接、以及全部 HUD 图标同步尚未完成跨 Demo 验收。本版本不把这些项目声明为稳定修复。

## English

### Fixes

- Fixed firearm updates that reached the runtime but produced `changed_slots=0, verified=0` on a friend's machine. The stock weapon had no paint, seed or wear nodes, while Schema exposed no usable vector-append operation.
- Resolves and byte-verifies the current client's native `CUtlVector<CEconItemAttribute>::AddToTail`. Missing paint-kit (`6`), seed (`7`) and wear (`8`) nodes are created only when reflected offsets, element size and machine code match the verified baseline. Unknown layouts fail closed.
- Rollback does not shrink or corrupt an engine vector without an erase callback. Native tail nodes created by this tool are neutralized and reused on a later Update, preventing repeated growth.
- Removes the cause of the roughly 31 ms cosmetic-poll average seen in the supplied log: verified entity-ceiling discovery now populates the cache in the same pass instead of traversing the complete entity system twice.
- Retains v0.4.4 weapon/finish compatibility filtering, stock-weapon material initialization, modern/legacy mesh selection, isolated input panel and portable single-DLL loading.

### Knife-model development status

The independent knife-model chain is included in the v0.4.5 source and binaries. Knife model/finish transactions, resources, animation graph, lifecycle and HUD handoff code remain separated from firearms, gloves and finish-only knife updates. It is still **experimental**: first-deploy continuity after entity reconstruction, teammate-issued or `.drop` ownership handoffs, and all HUD icon transitions have not completed cross-demo acceptance. This release does not claim those cases as stable fixes.

### Files and loading

Release assets include the English and Simplified Chinese DLLs, a bilingual Windows x64 ZIP, an exact source snapshot and `SHA256SUMS.txt`. The ZIP retains the requested compiled filenames with spaces; standalone GitHub assets use stable hyphenated aliases because GitHub normalizes spaces. For a ZIP-extracted file, retain exactly one pair of ASCII double quotes:

```text
mirv_loadlibrary "D:\Lyan_nskinz v0.4.5 EN.dll"
```

Fully exit a CS2 process that loaded an older build before restarting it through HLAE. Load only one language DLL.

### Compatibility and requirements

Windows 10/11 x64; HLAE **2.191.1**; CS2 Steam Build **25000182**, Client/Server **2000899**, Patch **1.41.7.8**, Source revision **10948930** (2026-08-28); current `client.dll` SHA-256 `b8e2c009763e8cefb88d89a2bdcf452db17501553d473db6da060df8e6769eb4`.

The DLLs use static MSVC `/MT` and embedded panel shaders. No separate VC++ redistributable, DirectX SDK, .NET, Python or Visual Studio installation is required beyond Windows, CS2 and HLAE.

**HLAE `-insecure` offline demos only. Never use on VAC-protected or online servers.** A future CS2 update can change the required layouts and must be revalidated.

### Validation boundary

- The complete native suite covers missing stock-firearm attribute creation, repeated-update reuse, rollback, stale-entity rejection, material refresh, and development regressions for the knife graph/pair chain.
- Read-only binding evidence against the installed `client.dll` and `animationsystem.dll`, Release import auditing, isolated loading for both languages and headless UI rendering are release gates.
- The earlier stock AWP → BOOM case is user-confirmed. The friend-machine firearm/stutter correction was located from supplied logs and validated with offline regression and binary evidence; rendered acceptance on that machine is not claimed at publication time.
- Automated checks are not exhaustive visual certification of every demo, player, firearm, knife, finish, drop event or frame-rate condition.
