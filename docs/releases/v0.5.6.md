## 中文说明

v0.5.6 修复部分当前 CS2 Demo 在生成临时换肤 Demo 时出现的 `serialized entity length count mismatch: table has N, packet has M entries`。`updated_entries` 统计的是包内全部实体命令，其中 Leave-PVS／Delete 不一定携带可变长字段数据；不同包的 `serialized_entities` 长度表可能记录全部命令，也可能只记录真实序列化的 Update/Create 条目。旧逻辑强制两个数量完全相等，因此会把 `117 / 191` 这类合法稀疏表误判为损坏。

writer 现在会同时记录每条实体命令类型，并按当前包动态选择全条目、字段数据条目或包含 Delete 但排除 Leave-PVS 的长度布局。字段位数变化只应用到对应实体，数量不写死为 117；1、37、117 或任意 N 都使用相同映射。无法对应已知合法布局、varint 溢出或长度变成负数时仍会失败关闭，避免静默输出损坏 Demo。

主界面底部的运行时状态、Schema／实体系统、绑定与应用统计、运行时诊断和 Catalog 警告已整合到默认收起的“运行时调试信息”栏。编辑器状态仍直接可见，需要排查时可展开完整信息。

## English notes

v0.5.6 fixes valid current-CS2 demos failing Temporary Demo generation with `serialized entity length count mismatch: table has N, packet has M entries`. `updated_entries` counts every entity command in a packet, while Leave-PVS/delete commands do not necessarily carry variable-length field payloads. Depending on the packet layout, `serialized_entities` may contain one length per command or only lengths for actual update/create payloads. The old strict equality check therefore rejected valid sparse tables such as the reported `117 / 191` case.

The writer now records every entity command type and dynamically selects the full-entry, field-bearing, or delete-inclusive/non-leave layout used by that packet. Bit-length deltas are applied only to the corresponding serialized entity. No count is hard-coded: 1, 37, 117, or any N follows the same mapping. Unknown layouts, overflowing varints and negative adjusted lengths still fail closed instead of silently producing a corrupt demo.

Runtime state, schema/entity bindings, application counts, diagnostics and catalog warnings are now grouped inside a collapsed-by-default Runtime diagnostics panel. The editor apply state remains visible, and the full troubleshooting block can be expanded when needed.

The Source 2 writer suite passes `41/41`, including the exact `117 / 191` regression and parameterized coverage for 0–256 field entries. The nSkinz rewriter passes `11/11`; a 310 MB real CS2 demo was rewritten and reparsed successfully. Native regression, both language builds and local isolated load/headless WARP gates pass. The third-party demo shown in the report was not supplied, so that exact file remains a user retest boundary.
