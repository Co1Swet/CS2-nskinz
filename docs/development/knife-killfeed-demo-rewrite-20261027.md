# 临时 Demo 刀型与击杀信息同步修复

更新：2026-10-27。反馈版本：v0.6.4。状态：**离线修复、回归和 DLL 加载验证已完成；实际 CS2/HLAE 图标仍待画面验收。** 本修复纳入 v0.6.5 发布包。

## 根因与产物对比

反馈截图为 `codex-clipboard-39b4c40f-043e-4cae-95cf-74568a6d7d56.png`。朋友的原始 Demo 尚未提供，本次使用本机两份含刀局的真实录制复现。

旧版 `knife_fields` 只修改刀实体的模型、subclass、定义、物品身份和饰面，未同步 `player_death` 游戏事件。刀实体与击杀事件分别保存刀型信息，因此实体重建成功不能证明击杀图标已同步。

保存的原 v0.6.4 重写器和修复版使用相同录制及配置：玩家 `76561198990516643` 默认 T 刀换为爪子刀（507），饰面 570。在 tick 2244、2392 都观察到：

| 数据 | 原 v0.6.4 产物 | 修复版产物 |
| --- | --- | --- |
| 刀实体定义 | 507 | 507 |
| 事件 `weapon` | `knife_t` | `knife_karambit` |
| `weapon_itemid` | `0` | `14204636881280271459`，与刀实体 IDHigh/IDLow 一致 |
| `weapon_fauxitemid` | `17293822569102704699`，默认 T 刀 59 | `17293822569140060667`，爪子刀 507／饰面 570 |

两份产物的刀模型资源和实体定义相同。缺失项明确是击杀事件同步。本地产物证据位于 `build/knife-killfeed-20261027/old-new-evidence.json`。

## 实现

新增 `tools/nskinz-demo-rewriter/src/killfeed.rs`，通过临时 Demo 重写器的 `PACKET_MESSAGE` 回调持久化事件修改：

1. 从事件描述表动态读取事件 ID、字段名称、顺序及类型，不写死样本中的 ID 53 或字段序号。
2. 按事件发生时的攻击者槽位／Pawn 与控制器关系解析 SteamID、队伍，再匹配 T／CT 刀配置。CS2 类型 9 的槽位 0 有效；旧类型 3 用户 ID 不当作槽位。SteamID 为 0 的机器人不匹配玩家配置。
3. 仅对配置玩家的刀杀同步 `weapon`、存在的 `weapon_itemid` 和 `weapon_fauxitemid`，使用与刀实体相同的物品身份算法。
4. 用本机 `weapons.vdata` 核对全部 22 个支持刀型的事件名。M9、鲍伊、折刀、锯齿爪刀等名称不能直接照搬模型资源文件名。
5. 按原始 protobuf 字段范围替换目标值，保留其它字段和未知扩展字节。
6. 写出后独立读回所有死亡事件，检查顺序、tick、数量及完整预期内容。攻击者无法解析或字段类型不符时返回带 tick 的错误。

普通枪杀、未配置玩家刀杀、攻击／受害／助攻关系、爆头和穿烟等标记均保留。没有临时 Demo 刀配置时，不注册事件重写器。同刀型重建仍同步物品身份与饰面，使事件与已重建实体一致。

所有新增处理仅在**临时 Demo 离线重建及验证阶段**运行，不增加播放期间的每帧 Hook、实体扫描或 HUD 刷新；实时饰面代码没有接入此修改。默认 T／CT 手套及挂件保留已有临时 Demo 路径。

成功详情增加 `knife_killfeed_events`（匹配刀杀）、`knife_killfeed_rewritten`（实际修改）、`verified_death_events`（读回校验）三个计数。
