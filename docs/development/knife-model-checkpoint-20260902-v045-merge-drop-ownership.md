# 刀模续作检查点：合并 v0.4.5 并修复掉落刀换主误写（2026-09-02）

本检查点以已发布的 **v0.4.5** 源码为唯一基线，继续当前独立刀模链；没有把 v0.4.4 或更早的刀模快照反向覆盖到枪械修复上。本轮没有修改正式 `v0.4.5` 标签或 Release，也没有启动、控制或注入 CS2。

## 本轮解决的问题

队友发刀或 `.drop` 后，同一个世界刀实体可能保留地址、句柄和 creation tick，但所有者已经改变。旧退休路径只确认实体仍存在，就可能把旧玩家事务保存的物品定义和世界模型写回已经属于新玩家的刀，表现为：

- 队友发出的刀变成原皮或覆盖目标刀型；
- 新主人持刀后，旧玩家的退休回滚又把模型改回去；
- HUD 仍显示来源刀，或者世界刀、HUD 刀和涂装在不同时间分别变化；
- 新拾取的刀已经处于活动状态时，旧的收刀预武装租约没有及时释放。

本轮把“实体仍存在”和“实体仍属于原玩家”拆成两个条件：

1. `KnifeNativeHost::WorldOwnership` 在任何物品定义或世界模型回写前，重新验证场景 epoch、pawn/world 句柄、world creation tick、item-view identity、world owner handle、pawn controller SteamID 和 pawn handle。
2. 若确认实体已经换主，旧事务丢弃它对物品定义和世界模型的回滚所有权，不再向新主人实体写入旧值；旧 HUD 图仍按独立证据清理。
3. 若所有权字段暂时不可读，退休操作进入 `Waiting`，不会猜测、不会写入；下一安全点重新验证。
4. 原子修改物品定义和世界模型前各再检查一次所有权，缩小验证后换主的竞态窗口。
5. 收刀预武装状态也使用同一类所有权分类。换主时放弃旧恢复账本并释放本 DLL 创建的属性记录，不把源玩家的刀型或原皮写回新玩家。
6. 新拾取的刀已经是活动刀时，也会先比较并清理旧的预武装租约，再进入活动刀生命周期；不会因“已经活动”的提前返回漏掉旧实体。

## 链路隔离

本次修改只进入独立刀模链的 `KnifeNative` 退休、生产原生 Host 和 holstered pre-arm 所有权路径：

- 枪械涂装仍走 `WeaponAppearance` 和标准枪械属性刷新链；
- 手套仍走 `GloveAppearance`；
- 刀的“仅饰面”仍只提交 paint kit、seed、wear 等外观字段，不出现或执行刀型请求；
- “饰面＋模型”才同时拥有独立刀模请求和刀饰面请求，两者不共享回滚账本；
- 本轮没有把通用枪皮实体扫描、手套模型或旧全局资源替换路径并入刀模状态机。

## 回归覆盖

新增原生退休测试覆盖：

- 世界刀确认换主后返回 `Discarded`，不改新主人刀的物品定义和模型，同时仍清理旧 HUD 图；
- 换主丢弃具有幂等性，重复退休不会产生新写入；
- 所有权暂时不可读时返回 `Waiting` 且零写入，恢复可读并确认仍归原玩家后才允许回滚；
- 测试 fixture 中的定义交换和 `SetModel` 也强制经过所有权判定，防止模拟器绕过生产约束。

验证结果：

- 定向刀模：3 个入口通过；刀模 11 组、刀图/原生端口/退休/生命周期 15 组、成对事务 6 组；
- 22 个刀型的 484 个有向配对模拟通过；这些是事务覆盖，不等同于实机动作验收；
- 枪械涂装定向 9 项通过；
- 完整 48 项回归通过，耗时 100.688 秒；
- 使用当前安装的 `client.dll` 和 `animationsystem.dll` 做文件证据检查，未加载游戏进程；
- 中英文 DLL 均为 x64 `/MT`，只直接依赖 Windows 收件箱 DLL；HLAE 风格 `LoadLibraryW`、System32-only、中文路径/空格路径、CRT 线程回调、卸载和离屏 WARP/ImGui 测试全部通过。

验证报告位于 `build/knife-v045-merge-dev/validation/`。

## 下一段实机验收与续作边界

后台测试已证明代码不会因旧事务向换主实体回写，但下列视觉结果不能由离线单元测试替代，仍需在 HLAE `-insecure` 离线 Demo 中验证：

1. 队友发刀、`.drop`、目标拾取、再切枪/切刀后，目标刀型和所选涂装是否持续保持；
2. 从枪第一次切到预武装目标刀时，deploy 是否从第 0 帧就使用目标刀图，而不是先播放默认 CT/T 匕首动作；
3. 右侧 HUD 在实体换主、seek、玩家切换和刀重新创建后是否始终跟随目标刀型；
4. 连续切刀、检视、轻/重攻击、特殊检视和多次拾取期间的帧时间。

下一次继续时，应先读取本检查点和 `knife-model-checkpoint-20260901-first-deploy.md`，结合新开发 DLL 的日志判断 pre-arm 账本是否成功交给活动 `KnifeLifecycle`。不要重新启用旧的全局资源替换或 sequence 映射方案，也不要把 HUD 刀当作世界 CEconItemView 写入。
