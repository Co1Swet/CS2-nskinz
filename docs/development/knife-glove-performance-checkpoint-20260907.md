# 刀模、手套可见链与掉帧修复检查点（2026-09-07）

本检查点接续 `knife-model-checkpoint-20260904-first-frame-m9.md`。用户最近的实测结果为“刀和手套都无效”；朋友机另报告加载 DLL 后 Demo 持续严重掉帧，但未闪退。本轮只在后台编译和运行离线测试，没有启动、注入或操作 CS2，因此不把测试程序通过表述为 Demo 画面验收成功。

## 本轮实现

- 刀模生命周期：保留同一场景、同一所有者、同一实体代际的收刀预装状态；主动刀具备已验证序列化桥时，不再被旧的“必须等待收刀预装”门槛永久拦截。
- 刀回调过滤：活动事务只接受同时匹配目标 controller/world 的原生回调；收刀预装只接受已租用的 world 实体。没有目标时不再派发手臂边界或状态机。
- 手套可见链：连接已核对的 `C_CSPlayerPawn + 0x1518` 原生手套组件，每个场景/请求/实体代际最多调用一次重建函数。必须同时观测到组件输出实体和 HUD 手套实体的目标模型，才记为已应用。
- 模型名规范化：手套校验同时接受 `.mdl` / `.vmdl` / `.vmdl_c` 资源名的等价形式，避免 CT/T 默认手套被文件后缀误判为无效。
- 实体扫描：安装的 86 字节 getter 证据完整匹配时，用一次 SEH 保护的 512 槽块扫描取代每槽多次安全读取；每个 identity 仍校验句柄的低 15 位实体索引，且指针不跨轮询保存。证据不匹配时保留原有慢速路径。
- 轮询频率：配置与手动更新仍立即触发；稳态维护扫描统一为 250 ms，而切刀交接继续由精确原生回调驱动。
- 手套工厂：不再仅因配置了手套就预先扫描 `CEconWearable` 工厂。只有 Pawn 原生载体实际不可用时才启用旧工厂后备，避免旧日志中出现过的约 202 ms 渲染线程探测峰值。
