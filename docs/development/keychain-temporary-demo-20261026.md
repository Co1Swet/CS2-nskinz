# 挂件仅临时 Demo 重建与播放开销修正（2026-10-26）

## 当前实现

挂件新增、替换、清除均接入临时 Demo 重写。DLL 播放期间不修改挂件属性、不刷新挂件模型、不创建挂件模块，也不因挂件配置单独启动深度实体扫描。此策略由 `runtime::kKeychainsTemporaryDemoOnly` 集中声明；旧挂件控制器和底层属性／模块写入口均受此策略保护。

用户流程：配置 XUID、枪型和挂件，点击“生成并加载临时 Demo”。已有挂件保留源位置、seed 和附加属性；明确清除与“不修改”分别处理。只点击“更新”不会实时替换挂件。升级候选 DLL 后应重启 CS2/HLAE，再从原始录制重新生成临时 Demo。

首次测试 DLL 采用 0.6.3 内部版本号和 `keychain-demo` 文件后缀；上述实现现纳入 v0.6.4 发布源码与说明。本页保留首次构建和离线回归的证据；v0.6.4 双语发行 DLL 另外执行加载／离屏渲染检查。

## 重写细节

- C++ 请求 schema 升级到 2，Rust 同时接受 schema 1 和 2。
- 挂件使用单独的 `keychains` 请求数组；挂件配置可以独立生成任务，不会合成涂装、品质、名称或贴纸修改意图。同一枪型的挂件任务与枪皮／贴纸任务可以合并执行。
- 按每条记录的实际属性定义和向量长度查找槽位，先纳入同次枪皮／贴纸追加，再分配挂件属性，避免索引碰撞；挂件路径支持超过 64 个属性的向量，上限为 4096。
- `299/306/314/321` 的整数联合体原始位与 `300/301/302` 的浮点位分别处理。仅换 kit 时保留原始位置和 seed；清除将已有挂件 ID／附属 sticker 清零，原本为空时不凭空追加空挂件。
- 无挂件武器使用对应模型 `KeychainMarkup` 中显式标记 `DefaultLocation = true` 的区域中心作为起始位置。现代／legacy 模型分别取值；mesh mask 1 对应现代，2 对应 legacy。
- 34 种枪械的源资源已与本机 VPK 核对。AUG 的新版资源需要官方 Source2Viewer 20.1 读取；重提取后确认默认坐标未变化。生成器隔离 DATA 元数据，避免无关 RED2 编辑器数据影响挂点提取。仓库仅保存派生坐标、骨名与资源哈希。
- 为修改后的物品生成含武器完整 handle、kit 和 XUID 的确定性身份，避免同型号的不同枪共用同一缓存身份；保留未请求的物品定义、品质、名称与饰品属性。
- 每个 Created、独立 FullPacket 快照和必要的后续属性覆盖均处理；普通无变化更新不重复追加字段。
- 输出后通过只读 DemoWriter 验证所有目标实体记录及全快照，不把线性解析某时刻出现过正确 ID 当作整份文件通过。
- 同一物理武器若被不同配置要求永久写入互相矛盾的挂件，明确拒绝，而不依赖 HashMap 顺序随机选款。

## 卡顿相关修正及证据边界

历史 `build/Release/nSkinzCS2.log` 在 2026-10-25 记录过实体工厂阶段约 327–335 ms 的长帧。同时间普通实体扫描约 0.04 ms，不能把这次尖峰归因于常规扫描。

本次改动：

1. 挂件彻底退出实时控制器、配置匹配与挂件专用扫描，不对播放中的实体持续覆盖字段。
2. 实体工厂帧回调在读取整份配置之前先检查原子请求标记；没有请求或正在播放生成 Demo 时立即返回，避免每帧复制配置、申请字符串／数组和获取配置锁。
3. 外置重写进程使用 `BELOW_NORMAL_PRIORITY_CLASS`；生成与验证继续在独立进程中完成。

这些改动消除了明确不需要的工作。没有本轮新 DLL 的 CS2 游戏内帧时间实测，因此不能声称已消除所有卡顿，也不将离屏 WARP 测试当作游戏 FPS 测试。
